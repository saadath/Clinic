# نقشه راه مرحله‌ای و معیار پذیرش

طبق prompt.md، پایان هر مرحله نقطه بازبینی است و شروع مرحله بعد نیازمند تأیید کاربر است. تست و کنترل دسترسی از همان مرحله مرتبط انجام می‌شود. زمان‌بندی تقویمی پیش از روشن‌شدن دامنه و منابع اجرا تخمین قطعی ندارد.

## ترتیب اجرای مرحله اول پس از تأیید

۱. بررسی نسخه و نصب PHP، Composer، Git و MySQL؛ انتخاب Node LTS سازگار و ثبت نسخه‌ها.

۲. ساخت Laravel و تنظیم `.env.example` بدون secret؛ ایجاد دیتابیس و کاربر محلی با دسترسی محدود به دیتابیس پروژه. رمز واقعی در مخزن قرار نمی‌گیرد.

۳. نصب وابستگی‌های frontend، Tailwind و فونت محلی؛ تنظیم ترجمه و layout و تم.

۴. احراز هویت کارکنان بدون ثبت‌نام آزاد، سپس تست ورود، CSRF، نرخ درخواست و session.

۵. اجرای build و تست‌های مرتبط، مستندسازی دستورهای اجرا و تحویل خروجی قابل مشاهده؛ توقف برای تأیید مرحله دوم.

## تصمیم‌های قابل نهایی‌سازی در مراحل مربوط

نام و نشان کلینیک، درگاه و پیامک، محل سرور، حجم فایل و تعداد هم‌زمان کاربران، سیاست دسترسی مشترک پزشکان، مدت نگهداری و رضایت ارسال AI، هدف backup و جزئیات امضای حقوقی پیش از بهره‌برداری تعیین می‌شوند. نبود این موارد مانع شروع زیرساخت با داده ساختگی نیست. درگاه، مدل ابری و OCR خارجی بدون تنظیم و تست واقعی «آماده اتصال» خواهند بود و موفقیت عملیاتی ادعا نمی‌شود.
