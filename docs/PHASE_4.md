# مرحله چهارم — فرم‌ساز نسخه‌دار

## امکانات پیاده‌شده

پزشک و مدیر مجاز می‌توانند قالب بسازند، بخش و فیلد اضافه کنند، ترتیب فیلدها را با کشیدن دستگیره یا دکمه بالا/پایین تغییر دهند، ستون و عرض را تعیین کنند و پیش‌نویس را ذخیره و منتشر کنند. هر ذخیره revision را افزایش می‌دهد؛ ذخیره یا انتشار با revision قدیمی پاسخ 409 می‌دهد. نسخه منتشرشده تغییر نمی‌کند و ویرایش قالب، پیش‌نویس نسخه بعد را باز می‌کند.

تنظیمات شامل عنوان، کلید داخلی، توضیح، نوع، مقدار پیش‌فرض، حداقل/حداکثر، واحد، گزینه‌ها، وضعیت، الزام مقدار، دسترسی دستیار/منشی، محرمانگی و تنظیم خروجی است. شرط ساده از رابط و شرط مرکب و فرمول از JSON پیشرفته تنظیم می‌شوند. فرمول فقط چهار عمل اصلی، عدد و ارجاع عددی را می‌پذیرد؛ کد دلخواه اجرا نمی‌شود. برای BMI وزن بر حسب kg و قد بر حسب m وارد می‌شود؛ تبدیل خودکار واحد انجام نمی‌شود.

قالب را می‌توان غیرفعال، برای کاربرد encounter/history/examination پیش‌فرض یا برای پزشک دیگر قابل کپی کرد. اشتراک فقط اجازه کپی تعریف آخرین نسخه منتشرشده می‌دهد؛ دسترسی به نمونه‌ها یا ویرایش اصل نمی‌دهد. لغو اشتراک کپی‌های مستقل قبلی را حذف نمی‌کند. تنظیم AI در کپی پاک می‌شود. غیرفعال‌سازی، پیش‌فرض را حذف و ثبت نمونه جدید را متوقف می‌کند؛ سوابق موجود خواندنی می‌مانند.

نمونه‌های فرم به نسخه ثابت متصل‌اند و ثبت‌کننده دارند. فرم داخلی شامل شرح حال، حساسیت شرطی، معاینه، وزن/قد، BMI و داروهای تکرارشونده است؛ فرم چشم مستقل شامل VA، IOP، Slit Lamp و Fundoscopy است. شناسه ردیف تکرارشونده مستقل از ترتیب آن است.

## روش استفاده

1. با حساب پزشک یا مدیر مجاز وارد شوید و «فرم‌ها» را باز کنید.
2. قالب ایجاد کنید، تنظیمات را تغییر دهید و «ذخیره پیش‌نویس» را بزنید. پیش‌نمایش، آخرین نسخه ذخیره‌شده را نشان می‌دهد.
3. پس از ذخیره، «انتشار» را بزنید. در پیش‌نمایش منتشرشده، داده ساختگی وارد و نمونه را ذخیره کنید؛ داده واقعی بیمار وارد نکنید.
4. از فهرست فرم‌ها ویرایش را باز کنید تا نسخه جدید ایجاد شود. نمونه قبلی همچنان نسخه قبلی را نمایش می‌دهد.
5. در پایین ویرایشگر، نام/فعال‌بودن، کپی، اشتراک/لغو و پیش‌فرض را تنظیم کنید. کپی به نسخه منتشرشده نیاز دارد.

برای ساخت نمونه‌ها پس از ایجاد پزشک فعال با نقش و مجوز لازم:

```powershell
php artisan db:seed --class=ExampleFormSeeder --no-interaction
```

Seeder برای هر پزشک واجد شرایط دو قالب مستقل ایجاد می‌کند و نام موجود را دوباره نمی‌سازد. بدون پزشک واجد شرایط، داده‌ای ایجاد نمی‌کند.

نمونه فرمول BMI در تنظیم `calculation`:

```json
{"op":"/","left":{"field":"weight"},"right":{"op":"*","left":{"field":"height_m"},"right":{"field":"height_m"}}}
```

## ساختار اجرایی و تفاوت با طراحی اولیه

- `app/Services/Forms`: ثبت نوع، اعتبارسنجی schema و وابستگی، کنترل دسترسی، چرخه نسخه و اجرای سروری.
- `app/Http/Controllers/Modules/Forms` و `app/Http/Requests/Modules/Forms`: مسیرهای وب و ورودی معتبر.
- `app/Models/FormTemplate.php`، `FormVersion.php`، `FormSubmission.php`: قالب، نسخه و نمونه.
- `resources/views/forms` و `resources/js/form-*.js`: طراح Alpine و renderer مشترک نمونه/پیش‌نمایش.
- `database/migrations/2026_11_17_103757_create_form_builder_tables.php`: قالب‌ها، نسخه‌ها، اشتراک، پیش‌فرض و نمونه‌ها.
- `database/seeders/ExampleFormSeeder.php` و `tests/Feature/Forms/FormBuilderTest.php`: مثال‌های مستقل و آزمون‌های رفتاری.

بخش و فیلد در `form_versions.schema_json` یک منبع تعریف دارند؛ جدول جداگانه قابل ویرایش برای آن‌ها ساخته نشده تا با snapshot رقابت نکند. به‌جای افزودن SortableJS از drag/drop بومی و دکمه‌های جابه‌جایی استفاده شده است. `form_submissions.values_json` به‌صورت متن JSON با cast آرایه و اعتبارسنجی برنامه ذخیره می‌شود؛ MySQL ترتیب کلیدهای object در ستون JSON را بازچینی می‌کند، ولی متن ترتیب ردیف‌های تکرارشونده را حفظ می‌کند.

## محدودیت‌های صریح

- نمونه‌ها پرونده پزشکی نیستند و بیمار/مراجعه ندارند؛ اتصال به پرونده در مرحله ششم انجام می‌شود.
- نوع‌های فایل، تصویر، PDF، صوت، ویدئو و امضا در schema ثبت می‌شوند، ولی آپلود/امضا در این مرحله فعال نیست. فیلد فایل اجباری، ثبت نمونه را با پیام روشن متوقف می‌کند.
- Rich Text فعلاً textarea است و HTML هنگام ذخیره به متن ساده تبدیل می‌شود؛ ویرایشگر غنی آماده نیست.
- Number Range فعلاً یک مقدار عددی دارای حداقل/حداکثر است؛ مقدار دو سر بازه نیست. Slider کنترل بومی مرورگر است.
- تاریخ/زمان ورودی بومی میلادی دارد؛ انتخابگر شمسی فرم‌ساز آماده نیست.
- ساختاری مانند شرط مرکب، پیش‌فرض چندانتخابی و تنظیمات کامل فرزند تکرارشونده از JSON پیشرفته انجام می‌شود؛ رابط ساده فرزند فقط متن/عدد را ارائه می‌کند. JSON نیز همان اعتبارسنجی سرور را می‌گذراند.
- AI فقط تنظیم enabled/methods/task/review_required را نگه می‌دارد؛ Provider، مدل، prompt نسخه‌دار و اجرا در مراحل AI تکمیل می‌شوند. `exportable` برای مرحله خروجی نگه‌داری می‌شود و اکنون خروجی سند نداریم.
- محاسبه با ورودی ناموجود/نامعتبر، تقسیم بر صفر یا نتیجه خارج از محدوده خطا می‌دهد. از داده شرطاً پنهان در شرط‌های بعدی یا محاسبات استفاده نمی‌شود.
- حذف فیزیکی قالب و audit جامع ارائه نشده؛ غیرفعال‌سازی موجود است. قفل و تغییرناپذیری از مسیر سرویس و مدل اعمال می‌شود؛ SQL مستقیم ادمین دیتابیس از این قواعد عبور می‌کند.
- آزمون‌ها درخواست HTTP، نمایش Blade و دیتابیس را پوشش می‌دهند؛ بررسی تعاملی drag/drop در مرورگر با حساب واقعی انجام نشده است.

## بررسی انجام‌شده

۱۷ آزمون فرم‌ساز با ۱۲۴ assertion؛ کل مجموعه ۸۱ آزمون با ۵۱۸ assertion روی SQLite حافظه‌ای و MySQL مستقل `clinic_testing` موفق شد. ساخت Vite و Pint موفق شدند. پوشش شامل جداسازی پزشکان حتی با مجوز فهرست عمومی پزشکان، فیلد محرمانه/فرزند، پایان همکاری، ورودی جعلی، شرط پنهان، انواع داده، پاک‌سازی متن، کپی/لغو اشتراک، غیرفعال‌سازی/پیش‌فرض، قفل revision، حفظ نسخه اول و ترتیب تکرارشونده روی MySQL است.

```powershell
php artisan test --compact tests/Feature/Forms
php artisan test --compact
npm.cmd run build
php vendor/bin/pint --dirty --format agent
```

تست MySQL فقط با `DB_CONNECTION=mysql` و `DB_DATABASE=clinic_testing` اجرا شود؛ تست‌ها دیتابیس آزمایشی را بازسازی می‌کنند. migration و RoleSeeder و ExampleFormSeeder روی توسعه اجرا شدند. Seed نمونه فقط برای پزشک واجد شرایط داده می‌سازد؛ برای آزمون‌ها داده‌های factory استفاده شده‌اند.

Git روی شاخه `main` فعال است. ثبت اولیه `fa45aca` مراحل یک تا سه و شروع ناتمام مرحله چهارم را نگه می‌دارد؛ تغییرات بعدی با commit جدا ثبت می‌شوند. `.env`، داده دیتابیس، runtime، وابستگی‌ها و build وارد تاریخچه نمی‌شوند. مخزن راه‌دور و push تنظیم نشده است.
